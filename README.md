# Whisper 录音与语音编辑

在 Mac 终端中通过键盘控制麦克风录音，使用 Whisper 转写，再用 LLM 校对文本。转写完成后，可以继续口述编辑要求，修改最近一版结果。

## 启动

准备 Python 3.11 或更新版本，以及可调用 OpenAI API 的 API Key。在项目目录打开终端并运行：

```sh
./start.sh
```

启动脚本会创建 `.venv`，按 `requirements.txt` 安装依赖，然后启动程序。首次安装需要联网。脚本也支持从其他工作目录通过完整路径运行。

程序优先读取环境变量 `OPENAI_API_KEY`。如果未设置，会提示输入，输入内容隐藏显示。Whisper 和 LLM 共用这个 Key。首次录音时，允许当前终端应用访问麦克风。

## 按键操作

保持终端窗口处于输入焦点。

| 当前状态 | 按键 | 操作 |
| --- | --- | --- |
| 等待录音 | Enter | 开始新一轮转写 |
| 录音中 | Enter | 停止录音并开始处理 |
| 已有结果，等待录音 | 空格 | 立即开始录制对最近一版文本的编辑指令 |
| 程序运行中 | Ctrl+C | 退出程序 |

新一轮录音处理完成后，终端依次显示 ASR 原始结果和 LLM 校对后的最终结果。

语音编辑会先显示 ASR 识别到的编辑指令，再显示编辑后的完整文本。可以连续多次按空格录制指令，每次都基于最近一版结果修改。例如：

1. 转写结果为“李详明天来吗？”。
2. 按空格，说“去掉最后的问号”，按 Enter 停止，得到“李详明天来吗”。
3. 再按空格，说“祥是吉祥的祥”，按 Enter 停止，得到“李祥明天来吗”。

按 Enter 开始新一轮录音后，新产生的结果会成为后续编辑的目标。

## 提示词配置

编辑项目根目录的 `whisper_config.toml`，保存后重新启动程序生效。提示词支持在 TOML 三引号字符串中写多行文本。

| 配置项 | 用途 |
| --- | --- |
| `prompt` | Whisper 的识别参考信息，可填写人名、术语和录音上下文，也会提供给后续 LLM |
| `llm_model` | 校对和编辑使用的 LLM，默认 `gpt-6-luna` |
| `llm_prompt` | 首次转写后的校对提示词 |
| `llm_edit_prompt` | 根据口述指令编辑当前文本的提示词 |

例如，Whisper 提示词可以写成：

```toml
prompt = """
本次讨论 OpenAI、Whisper 和 MaxCompute 的接口。
"""
```

`prompt` 留空表示省略识别提示。其他三个配置项需要填写非空文本。

初版校对提示词要求保留原意，修正有依据的错字、术语和标点。编辑提示词要求仅修改口述指令涉及的部分。程序会自动把文本和上下文传入 LLM，无需在提示词中填写模板占位符。

Whisper 使用 `whisper-1`。LLM 通过 Responses API 调用，语音编辑需要模型支持 JSON Schema 结构化输出。修改 `llm_model` 时，请选择账户可用且支持这些能力的文本模型。

## 文件结构

```text
.
├── README.md
├── start.sh                 # 启动、准备虚拟环境并安装依赖
├── requirements.txt         # Python 依赖
```

`.venv`、`work` 和 Python 缓存由 `.gitignore` 排除。

## 运行说明

- 使用系统默认输入设备录音，单段 WAV 音频上限为 25 MB。录音时会提示当前设备采样率对应的大致时长上限，长录音请分段处理。
- 音频和当前文本在内存中处理，结果显示在终端中，需要留存时可以复制文本。
- 校对调用失败时，使用 ASR 原文作为当前结果。编辑调用失败时，保留上一版文本，可以再次按空格重试。
- 出现录音错误时，检查系统默认输入设备及终端应用的麦克风权限。出现 API 错误时，检查网络、Key、账户额度及模型访问权限。
